# Unity 0.2.2 Beta · Minecraft Java 26.2

本版修复了配置连接关闭、配置文件监听和客户端破坏方块的边界问题，并扩展了原始 JAR 的识别与加载。游戏运行在独立加载器上，使用 Java 25。

## 配置连接、文件监听与玩法

| 场景 | 本版行为与验证 |
|---|---|
| 握手过程中断开 | 连接状态、协商结果、接收器与终止权在同一个会话锁下更新。生命周期回调与网络发送在锁外执行。并发回归分别阻塞在握手更新和完成回调处，再触发关闭，检查会话不复活且终止回调只执行一次。 |
| 可选通道满额 | 保留全部 256 个 Play 名额。常规规模沿用已有编码，满额且开启 Configuration 时，框架能力使用独立的字段。实机测试中保留作者原有的 2 个可选通道，再通过 SDK 注册 254 个。一次主动中断后，两位玩家首次入服和重启回服都完成了协商。满额扩展格式需要客户端和服务端都支持。 |
| 热重载与切换世界 | 新建监听前关闭旧 WatchService，路径统一为规范化绝对路径。关闭等候正在执行的轮询，随后卸载配置。测试覆盖相对路径、旧服务句柄、回调中再次查询配置，以及关闭后的 Tick。 |
| 方块破坏、经验与放置 | 客户端玩家或非服务端世界沿用原版破坏与收获路径。两个真实客户端都验证了一次原版收获调用。嵌套放置按捕获快照的对象身份撤销，避免误删内容相等的另一笔变更。 |
| 发送缓冲区 | 自定义编解码器写入有上限的临时 Netty 缓冲区，编码成功后才提交通道头和包体。Configuration 与 Play 均保留各自的缓冲区类型。两种协议、两个方向的越界回归均检查了原输出没有部分写入。此上限约束 Unity 提供给编解码器的包体缓冲区。 |

双端实机记录还包含配置版本不匹配拒连、玩家重新登录、两个背包、世界附件和容器库存的复验。[实机记录](../evidence/0.2.2-Beta/candidate65.json) · [并发与边界测试](tests/ReviewChecks.java)

## 归档、元数据与依赖求解

- Forge、NeoForge 的模组声明、Mixin 清单和 Access Transformer 清单统一使用随包的 NightConfig TOML 解析器。转义引号、多行字符串、内联表、数组、布尔和数字可按 TOML 语法读取。Unity 对自己消费的字段继续按平台类型校验，对未知的条件转换声明会明确报错。[NightConfig 项目](https://github.com/TheElectronWill/night-config)
- 一个 JavaFML JAR 可以声明多个模组，各自按 ID 绑定入口、元数据和依赖。同一归档的资源挂载一次。多模组 Forge JAR 中的自动事件订阅者需要声明所属 mod ID。
- Java 多版本 JAR 的类索引、ABI 预检和运行时读取得到同一个有效视图。实测的单包双 Forge 模组同时含有基础、Java 25 和更高版本层，专服和客户端均选中了 Java 25 的类和资源。另一个双 NeoForge 模组探针验证了名称中的引号，以及多行简介中外观类似配置表的普通文字。
- 对齐 Fabric 与 FML 描述符 ID 和版本、只含数据且没有代码入口、内嵌库和转换器的通用 JAR，可作为原版数据包挂载。Minecraft 按数据包格式选择 overlay。本版实际装入作者发布的 **Craftable Trident** 原始 JAR，让原版合成管理器匹配九宫格材料并合成一把三叉戟。该样本只安装在专服，客户端使用原有 65 模组测试包的客户端清单。[作者版本、来源和 SHA-512](universal-data-sample.json)
- 嵌套依赖先按已知版本范围过滤候选，再选择可用版本最少的依赖。回溯修改一份选择表，成功时才复制结果。在 24 组各有两种版本、另有一个传递约束的测试图中，26 个搜索状态得到正确解。求解器保留复杂度上限。
- 关闭归档时保留第一个失败，并在 suppressed 列表中保存后续关闭错误。自定义资源 URL 改用 Java 25 的 `URL.of`，缺失条目和已经关闭的 JAR 分别给出包含资源路径的异常。[Java URL API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/net/URL.html)

## 开发与升级

经验区间字段及创造栏的展示、搜索集合在注册表启动阶段检查名称和类型。运行时复用解析过的字段。项目根目录增加 `.clang-format`，开发时可以对修改的 Java 文件运行以下命令。普通构建仍使用 JDK。

```powershell
clang-format --style=file --dry-run --Werror standalone/src/main/java/mc/unity/core/ConfigurationNetwork.java
```

## 验收范围

专服测试装入 65 个含 Java 代码的作者模组、8 个依赖和额外的 1 个作者纯数据 JAR。SDK 探针另计。两台隐藏客户端验证远程连接，单人客户端在同一进程中创建 A、创建 B、重新打开 A。性能对照沿用相同的 65 模组清单和原版存档，每组采集 1,200 个双人步行 Tick。[65 模组清单](performance-pack.json) · [单人记录](../evidence/0.2.2-Beta/integrated.json)

带多平台可执行入口的通用 JAR、Kotlin 加载器、任意版本前置库、注册表按名称重新映射以及拒连时列出完整缺失模组清单，仍是后续兼容工作。本版未扩大先前的通用注册表及客户端渲染 API 覆盖。
